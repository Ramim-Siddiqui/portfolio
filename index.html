01

Voice AI Patient Registration Agent

A phone agent that registers patients through natural conversation.

Overview

Callers dial a real U.S. number and talk to Riley, an intake coordinator built on Vapi. Riley collects the standard patient demographics in any order, spells names back, rejects impossible answers such as a birth date in the future, reads everything back for confirmation and only then writes the record. Returning callers are recognised by phone number and must confirm their date of birth before anything is changed.

Highlights

  • Tool-calling agent with five backend tools: patient lookup, registration, update, appointment slots and booking.
  • One validation layer shared by the voice tools and the REST API, so the phone channel can never store what the API would reject.
  • Honest failure handling: when a write fails the agent says so and offers a retry; it never claims success.
  • Transcript, summary and cost stored for every call and shown on a live dashboard.

Built with Python · FastAPI · Vapi · SQLAlchemy · PostgreSQL · Vercel

02

Support Ticket Resolution Agent

An agentic workflow that drafts support replies and checks its own work.

Overview

A LangGraph state machine classifies each ticket, retrieves the matching knowledge-base passages with Gemini embeddings, drafts a reply with Gemini and reviews the draft against explicit rules: greet the customer, ground every fact in the retrieved context, never promise a refund. A failed draft is refined and retried; after two rejections the ticket goes to a human with the full trace logged.

03

MCQ Studio

Writes exam questions from textbooks, and pulls them out of old papers.

Overview

A FastAPI service I built at Gems Pathways for the company's learning portal. A teacher uploads a book as PDF, Word, Markdown or text; the service finds its chapters, stores the text as embedded passages in Qdrant, and writes multiple-choice questions spread across the chapters by the weightage the teacher sets. It also works the other way round, copying existing questions and their answer keys out of a question paper so an admin can review them.

Highlights

  • Chapter detection that tries PDF bookmarks, then a printed table of contents matched to the real pages, then headings and font sizes, and copes with books whose chapter numbers restart in every part.
  • Questions cover whole chapters: text is read in slices of about 12,000 characters, and embeddings pick varied slices when only a few questions are needed.
  • Every question is checked, near-duplicates are removed by wording and by meaning, and answer positions are balanced so A, B, C and D are each correct about equally often.
  • Five interchangeable AI providers: Gemini, Groq, OpenRouter, any OpenAI-compatible API or a local Ollama model. Extraction falls back to a rule-based parser when the quota runs out.
Design
Automated tests173, with a fake AI provider and no database needed
EmbeddingsBAAI/bge-small-en-v1.5, stored in Qdrant
InputsPDF, Word, Markdown and plain text
DeploymentDocker Compose, API key, ports bound to the server only

Built with Python · FastAPI · PyMuPDF · sentence-transformers · Qdrant · Gemini · Groq · Docker

04

Smart Attendance System

Face-recognition attendance from an ordinary CCTV camera.

Overview

A Windows desktop app that watches a CCTV camera or recorder, recognises the people enrolled from a few photos, numbers everyone else Unknown-1, Unknown-2 and so on, and logs when each person comes in and leaves. It runs on a normal PC with no GPU and no internet connection.

Highlights

  • SCRFD finds faces and ArcFace turns each one into a 512-number embedding, both on ONNX Runtime. A face is named when it is close enough to an enrolled person.
  • A tracker logs one visit per person: a face must appear in three frames before IN is written, two frames must agree on a name, and OUT is the last moment the person was seen.
  • Enrolment adds CCTV-like variations of every photo: dark, bright, blurred, distant, compressed, night-mode grey and noisy.
  • Finds cameras on the network, builds stream addresses for six recorder brands, reconnects after drops, and stores the camera password encrypted for the Windows user.
Design
RecognitionSCRFD and ArcFace (InsightFace models)
Runs onCPU, ONNX Runtime, no internet
OutputDaily attendance CSV and a snapshot of every visit
InterfaceTkinter, four tabs

Built with Python · OpenCV · ONNX Runtime · InsightFace · Tkinter

05

PortraitPass

Checks student ID photos and removes the background.

Overview

An API I built at Gems Pathways, called by the student portal when a photo is uploaded. It checks the photo against a portrait policy and returns either a clean transparent cut-out or a list of machine-readable reasons, such as a second person, a head turned away or a blurred shot, that the portal turns into instructions for the student.

Highlights

  • MediaPipe face and pose landmarkers scan the whole photo and a grid of overlapping tiles, so a second person in the background is still caught.
  • Head turn, nod and tilt come from the face landmarker's transformation matrix and must each stay within 25 degrees. Visible knees or ankles mark a full-body shot.
  • BiRefNet Portrait segments the person at 1024 by 1024 pixels; the mask is cleaned and feathered so hair survives.
  • Upload checks on format, size, dimensions, animation and decompression bombs run before any model does.
Design
ValidationMediaPipe Face and Pose Landmarker
SegmentationBiRefNet Portrait
OutputTransparent PNG, or rejection codes with messages
SpeedAbout 40 s per photo on a CPU; the live demo runs on a GPU

Built with Python · FastAPI · Gradio · MediaPipe · PyTorch · Hugging Face Transformers · OpenCV · Docker

06

Detecting Source-Code Vulnerabilities with Graph Neural Networks

Final-year research: graph classification over the syntax trees of C and C++ functions.

Overview

Each function in the Devign dataset, 27,318 functions from FFmpeg and QEMU, is parsed with libclang into an abstract syntax tree, linearised into node-kind and identifier tokens, and encoded as a PyTorch Geometric graph over a 54,823-entry vocabulary. A three-layer GraphSAGE network with global mean pooling then labels the function as vulnerable or not.

Results on 3,318 held-out functions
MetricValue
Test accuracy93.0%
Macro F10.93
Vulnerable class, precision0.90
Vulnerable class, recall0.96
Parameters≈28.2 M

The held-out functions are the last rows of the dataset, and near-duplicate functions were not removed, so these figures are an in-distribution estimate rather than a benchmark result. Published results on Devign's official split are much lower.

Built with PyTorch · PyTorch Geometric · libclang · scikit-learn · pandas

07

Smart Form Filler

Record one data-entry session, then replay it for every row of a spreadsheet.

Overview

Built at Gems Pathways for web portals that have no import feature and no API. The user signs in by hand, records a single entry and maps each typed value to an Excel column; the tool then drives a real Chrome window through every remaining row, verifies each submission and writes a status for every row. Interrupted runs resume where they stopped.

Highlights

  • A recorder injected into the page captures clicks, typed values, dropdowns and dates with stable selectors. Password fields are detected and never stored.
  • Automatic column matching, date reformatting and a per-row success check.
  • Up to nine copies run side by side, each with its own browser profile, login and ports.
Design
Browser controlPlaywright over the Chrome DevTools Protocol
InterfaceStreamlit, six guided steps
Parallel copiesup to 9

Built with Python · Playwright · Streamlit · pandas

08

GitHub Stars Crawler

Collecting star counts for up to 100,000 repositories in a CI pipeline.

Overview

A Python crawler that runs inside GitHub Actions next to a PostgreSQL service container. It queries the GitHub GraphQL API in date slices to get past the 1,000-result search cap, upserts every repository's star count, records its progress so a run can resume, and exports a CSV and a database dump as build artifacts.

Highlights

  • Date-sliced GraphQL search with cursor pagination.
  • Rate-limit aware: waits for the quota to reset and retries server errors with exponential backoff.
  • Idempotent upserts and a state table, so interrupted runs resume where they stopped.

Built with Python · GraphQL · PostgreSQL · GitHub Actions

Source code and workflow
